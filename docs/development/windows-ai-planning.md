# Windows development AI planning

This checkpoint extends the accepted saved workspace with a durable planning
conversation and a separate authenticated model-proposal adoption path. The
normal connection is **LIVE_ROUTE_BLOCKED**. Model and subscription eligibility
are unqualified; no API billing fallback is available. Synthetic fixtures prove
software behavior and do not prove an owned subscription connection.

From the repository root, launch with `npm run start:desktop`. Select a saved
project or create one using the existing repository picker, then open **AI
planning**. Describe the project and explicitly save the conversation. The
connection card explains why sending is currently unavailable.

With a separately qualified trusted host, each understanding or proposal request
requires native confirmation of the exact saved project context, model,
subscription implication and optional repository summary. A conversation allows
three explicitly initiated requests, at most two clarification rounds, and
three material questions per round. A new conversation needs new consent and
preserves the earlier conversation. No request is retried automatically.

The operator's description becomes the C8 objective only through explicit brief
acceptance. Model understanding, proposed outcomes, assumptions and questions
remain attributed to their source. Original wording stays model-authored when
collections are reordered. Edits to model prose are recorded separately.
Existing hard constraints keep their origin and authority.

The proposal is a genuine authority-none Thinker contribution. Explicit adoption
validates the immutable contribution, exact current project/brief/plan context,
fixed dependency graph and native confirmation, then writes through canonical
C9 persistence. It does not pass model text through manual `save-plan`. The
original model proposal and authenticated before/after field edits remain
available in saved history. Preparation, exact scope approval, sealing and
expired-request renewal are separate actions. Task budgets authorize zero
execution turns and zero tools.

Admission, dispatch, terminal state and contribution are separate durable
phases. Inference runs outside the SQLite transaction. A lost reply after
dispatch remains outcome/usage unknown; reopening starts no request. Stop and
cancel revoke adoption and attempt cancellation; late output cannot overwrite
newer edits. Reported usage is retained as evidence, not a subscription invoice
or fabricated remaining allowance. A provider cost estimate, when supplied, is
an API-equivalent estimate only.

Inputs, model output, deadlines and history have finite bounds. The app reserves
history space before dispatch. A bounded notes excerpt is labelled when some
text is omitted from the view; the original contribution stays saved. Reaching
a history cap refuses new work without replacing older records. Exported-file
differences remain warnings, while genuine store corruption remains protected.

The inspected signed Claude Code 2.1.263 interface supports print, structured
output and tools-disabled flags, but its safe/restricted modes still permit
managed commands. A supported effective-policy attestation or sufficient
isolated-process boundary has not been established. The shipped process port
therefore refuses before authentication helpers or inference. No private
credential/configuration inspection, managed-policy weakening, account switch,
API key or extra-usage purchase supplies an alternative route. The qualification
receipt and exact validation identities are held in the checkpoint's external
evidence packet.

The maintained Windows smoke uses a visibly labelled, owned synthetic port in a
dedicated test entry. Normal startup accepts no renderer, command-line or
environment switch that selects that fixture. CI makes no live model calls.
General production/coding dispatch and installer release remain disabled.
PLN-02 remains incomplete: this helper does not deliver ADR0016's planning
assembly or ADR0029's separately authorized final completeness audit.
