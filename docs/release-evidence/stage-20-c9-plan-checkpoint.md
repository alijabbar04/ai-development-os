## Lifecycle, seal, and persistence evidence

The implementation drives the seven named C6 cells and contains a complete 21
by 25 assembly table: 525 cells, exactly 107 legal transitions, and nine locked
states. Tests execute every legal cell and refuse all 418 null cells. Pending

accepted-brief, request/result, control, and non-null review evidence. Head

Inside the same C7 transaction, every write reparses the current Project,

version/content against the retained assembly basis. Injected faults between
aggregate and event append roll the transaction back. Paused, archived,
active-stop, stale-project, corrupt, cursor, unavailable, replay, forged-token,
and caller-refreshed stale-plan cases write nothing.

Seal evaluation uses the transactionally proven plan/review/brief/project,
current budget account, resolved ceiling, and capability-authenticated

ceilings: 60/60 refuses against total 100 while 60/40 passes. C9 creates no
reservation or spending entitlement. Durable scope approval is always null,

Direct and observational outcomes remain separate. Ambiguous head writes allow
only bounded exact head/event observation; ambiguous annotation allows only
bounded ascending journal observation. Exact target evidence commits, exact
unchanged prior state returns observational not-recorded, and incomplete,
contradictory, unavailable, cursor-faulted, duplicate, or bound-exhausted
evidence stays unknown. No observation writes and no retry occurs.

The testing composition has a finite 30-second evidence deadline by default,
with deterministic shorter bounds and a monotonic clock injectable by tests.
It checks before and after every awaited evidence read and immediately before
the first persistence mutation. Expiry detected before capability consumption
writes nothing and leaves the one-shot authorization reusable. The capability
is consumed before the single transaction attempt; expiry during that
transaction's evidence reads rolls back with zero mutation but leaves the
authorization consumed. Neither outcome retries automatically. The caller gets
an honest bounded refusal or not-attempted result and must obtain a fresh
authorization before any new attempt when the original was consumed. The C7
adapter has no cancellation parameter, so in-flight calls are awaited and never
detached; the guarantee is refusal before mutation after elapsed evidence, not
